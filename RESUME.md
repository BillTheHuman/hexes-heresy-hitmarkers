# Résumé and portfolio language for Hexes, Heresy & Hitmarkers

This file offers calibrated wording for a real technical project. It is not a
substitute for reviewing the exact job application, portfolio page, or public
repository description.

- **Release:** 1.0.0
- **Public repository:**
  [github.com/BillTheHuman/hexes-heresy-hitmarkers](https://github.com/BillTheHuman/hexes-heresy-hitmarkers)

## Accurate public-release wording

The following wording describes the released public package without implying
that its withheld implementation is public:

> Directed a first-party, AI-assisted static-recompilation study of an
> owner-attested Nintendo 64 cartridge input; validated bounded Linux graphics,
> audio, controller, persistence-context, and shutdown paths while preserving
> negative and unresolved results.

> Published a non-playable proof package with a versioned evidence format,
> claim ledger, deterministic verifier, release manifest, and tamper-oriented
> tests; excluded the cartridge image, game assets, translated code, executable,
> saves, and raw traces.

> Designed and tested a native startup settings and launch path using validated
> settings, descriptor-anchored no-follow storage, shell-free process spawning,
> explicit descriptor policy, and child lifecycle handling.

> Distinguished instrumented telemetry, source and executable inspection,
> participant attestations, AI-assisted screen observations, failed rechecks,
> and bounded inference instead of presenting first-party success as outside
> replication.

> Published a non-playable, machine-verifiable technical report documenting a
> private Nintendo 64 static-recompilation study, with structured evidence,
> contradiction criteria, tamper tests, explicit negative results, and a clear
> separation from protected game material.

Do not substitute “independently reproduced” unless an outside party has
actually reproduced the underlying execution. Publicly rerunning the evidence
verifier is not that event.

## Interview-ready project summary

> I treated publication as an engineering problem rather than simply uploading
> a private prototype. I built a claim-by-claim evidence layer, preserved a
> failed graphical recheck and an ambiguous shutdown event, and made the public
> verifier fail closed on missing, extra, altered, malformed, or misclassified
> records. The public package is intentionally non-playable: it demonstrates
> method, measurement, and epistemic discipline without distributing the input,
> translated program, assets, executable, or private evidence.

## Wording to avoid

Do not describe the project as a fully realized public port, a perfect or
complete reimplementation, an accurate replica, an independently reproduced
result, an unqualified absence of emulation, a conventional clean-room
implementation, or legally approved work. The evidence does not support those
claims.
